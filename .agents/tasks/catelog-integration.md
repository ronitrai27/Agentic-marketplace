### Mode
**async** by default, readable from `REVIEW_MODE` env var (`sync` | `async`).

### Key design decision — plain JSON Schema instead of Zod
CodeReviewAgent uses **zod v4** (`^4.6.7`). The `catelog` package internally expects zod v3 schema shapes, so passing a `z.object()` built with zod v4 would cause a runtime type mismatch.

The fix: `inputSchema` and `outputSchema` are defined as plain JSON Schema objects (`{ type: "object", properties: {...} }`) with TypeScript `as const` typing. This keeps full type-safety for the execute context while avoiding the zod v3/v4 conflict entirely. Catelog accepts any JSON Schema object in place of a zod schema.

### Files created
- `src/catelog-server.ts`

### Port
**3018** (overridable via `CATELOG_PORT`)

### Mode
Always **async** — hard-coded. The patent pipeline (`createAnalysis()` + `runAnalysis()`) takes 60–120 seconds, which is well beyond any reasonable sync timeout.

### Key design — wraps createAnalysis() + runAnalysis() pipeline
The agent does **not** call the patent pipeline directly. It:
1. Derives a `draftHash` from the input text
2. Calls `createAnalysis()` to insert a DB record and obtain `analysisId`
3. Calls `runAnalysis(analysisId)` to kick off the multi-stage pipeline (prior-art search, claim charting, novelty scoring)
4. Fetches the completed `AnalysisRow` via `getAnalysis()` and returns the structured result

Zod v3 is in use here (`^3.24.2`), which is compatible with catelog's expectations, so `inputSchema` and `outputSchema` are proper `z.object()` schemas.

## How to Run

```bash

cd Agents/CodeReviewAgent
npm run catelog
# → Listening on http://localhost:3016
# → Endpoints: GET /health  GET /schema  POST /execute  GET /tasks/:id

# Start the AiPatentAgent Catelog server
```

## Notes

### Zod version conflict (CodeReviewAgent)
CodeReviewAgent uses zod **v4** while catelog ships type definitions that reference zod **v3** internals. Passing a `z.object()` from zod v4 to `inputSchema` / `outputSchema` would produce a TypeScript error and potential runtime issues. The solution was to use plain JSON Schema objects instead, which catelog accepts as a valid alternative. This avoids adding a second copy of zod and keeps a single dependency version in the project.

### AiPatentAgent uses zod v3 natively
AiPatentAgent already had zod `^3.24.2` in its `package.json`, making it directly compatible with catelog's schema expectations. Zod schemas are used there without any workaround.

### No changes to existing servers
The catelog integration is a separate entry-point (`src/catelog-server.ts`) that is **additive only**. The original `src/server.ts` (Express) for CodeReviewAgent and `src/api/server.ts` (Fastify) for AiPatentAgent are completely unchanged.

### Dev-mode auth
When `CATELOG_SECRET_KEY` and `CATELOG_PUBLIC_KEY` are left blank, catelog runs in dev mode and skips authentication. This is safe for local development; add the keys from the Catelog dashboard before deploying to production.

### maxTimeoutMinute values chosen
- CodeReviewAgent: **5 minutes** — typical reviews complete in 10–30 s; 5 min is a safe ceiling
- AiPatentAgent: **10 minutes** — pipeline runs 60–120 s; 10 min gives headroom for slow prior-art fetches
